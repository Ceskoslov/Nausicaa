## Manual key-loading regression and correction

The earlier live scripts used Python `.strip()` when reading the key. They did
not exercise the documented shell loading path. The host's key file has CRLF line
endings: shell `$(cat ...)` removes LF but retains the trailing CR. Before the fix,
the TUI put that CR in the Authorization header, which the transport correctly
rejected before networking. This explains the manual-start failure with 0 ms total
and unavailable network phases; it was not a DeepSeek endpoint failure.

The TUI now trims only surrounding credential whitespace. Interior CR/LF remains
invalid. A live regression test used the original shell `$(cat ...)` expression,
asserted that the inherited environment key still ended in CR, and passed it
unchanged to the rebuilt TUI. DeepSeek returned exactly `OK`: first text 1364 ms,
total 1382 ms. Host-only evidence is
`.agent-harness/deepseek-manual-key-validation.json`. No key bytes were logged.
The local ignored Bash profile also removes a trailing CR for older binaries.
